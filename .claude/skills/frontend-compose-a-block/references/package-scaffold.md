# Package scaffold

A package is a directory at `packages/<name>/`, registered by the `packages/*` glob in
`pnpm-workspace.yaml` — creating the directory is the registration. Eleven files are always
required; unit tests, Relay, web styling, Cypress, and Storybook each add a set on top. Nothing
fails loudly when one is missing: the package still builds and publishes, it just silently skips
lint, tests, codegen, or the release.

## Directory shape

`+set` markers are conditional — see [Conditional file sets](#conditional-file-sets).

```text
packages/<name>/
├── package.json               # the whole contract: exports, files, catalog: deps, scripts
├── tsconfig.json              # extends @baseapp-frontend/tsconfig/lib.json; ESLint resolves it too
├── tsconfig.build.json        # tsconfig.json minus tests — what `tsc --build` targets
├── .eslintrc.js               # one-line re-export of the shared config
├── .prettierrc.js             # one-line re-export; root lint-staged prettifies packages/**
├── README.md                  # every package has one
├── CHANGELOG.md               # changesets appends here; seed it with the package name heading
├── .gitignore                 # copy a neighbour's; add the relay entries if the package uses Relay
├── modules/                   # source root — one dir per feature, each with its own barrel
│   └── <feature>/
│       ├── common/index.ts    # platform-neutral barrel — one `exports` subpath
│       ├── web/index.ts       # web barrel — one `exports` subpath
│       └── native/index.ts    # native barrel — one `exports` subpath
├── jest.config.ts             # +tests — re-export of the shared jest config
├── tsconfig.jest.json         # +tests — extends @baseapp-frontend/tsconfig/unit-test.json
├── __mocks__/                 # +tests — 9 shims, resolved against THIS package's rootDir
├── relay.config.js            # +relay — re-export of the shared relay config
├── schema.graphql             # +relay — committed, regenerated by relay:download-schema
├── babel.config.js            # +relay — plugins: ['relay']
├── __generated__/.keep        # +relay — artifacts generated, never committed
├── tailwind.config.js         # +web styling
├── postcss.config.js          # +web styling
├── cypress.config.ts          # +cypress
├── webpack.config.ts          # +cypress — the component-test bundler
├── cypress/support/           # +cypress — commands, component, component-index.html, types
├── .storybook/                # +storybook — main.ts, preview.ts
└── public/mockServiceWorker.js # +storybook — pair with the msw.workerDirectory field
```

## The 11 always-required files

| # | File | Why |
|---|---|---|
| 1 | `package.json` | The contract: `exports`, `files`, `catalog:` deps, scripts, `sideEffects`. |
| 2 | `tsconfig.json` | Extends `packages/tsconfig/lib.json`; ESLint resolves it as its project. |
| 3 | `tsconfig.build.json` | Extends `./tsconfig.json`, drops tests — `tsc --build` targets it. |
| 4 | `.eslintrc.js` | Re-exports `packages/config/.eslintrc.js` or its restricted-paths twin. |
| 5 | `.prettierrc.js` | Re-exports the shared prettier config; lint-staged runs on `packages/**`. |
| 6 | `README.md` | Every package ships one; `packages/graphql/README.md` is the template. |
| 7 | `CHANGELOG.md` | Changesets appends here; seed with the package-name heading alone. |
| 8 | `exports` map + `files` allowlist | The entrypoint. No `main`, no root barrel — see below. |
| 9 | An `index.ts` per source dir | The ast-grep rules assume the index/types/styled leaf layout. |
| 10 | `.changeset/<slug>.md` | Required before merge; the release workflow publishes from it. |
| 11 | A bullet in the root `README.md` | Its "Apps and Packages" list enumerates every package. |

Rows 10 and 11 live outside `packages/<name>/`. The other nine are files in the directory.

Every buildable package declares `build`, `dev`, `lint`, `clean`, and `storybook`, plus `test:unit`
when it has unit tests. Declare `storybook` even with no stories — the echo stub
`echo <Name>: No storybook found`, as in `packages/provider/package.json`. Without it nothing
satisfies the turbo `storybook` task.

**Shape B is the target for a new package**: an `exports` map whose targets are TypeScript source
subpaths, a `files` allowlist, `sideEffects: false`, and no `main`. That is what
`packages/components/package.json` and `packages/design-system/package.json` do — the two most
recently maintained packages. Counter-example: the six barrel packages (`authentication`, `graphql`,
`provider`, `test`, `utils`, `wagtail`) pair `main: "./index.ts"`, which is source, with
`types: "dist/index.d.ts"`, which is built, so the two fields disagree about what ships. Do not copy
that pair forward.

## Conditional file sets

Each set is additive on top of the 11. Add a set only when the package actually needs it.

### Unit tests — +5 files, +9 `__mocks__` shims

| Add | Why |
|---|---|
| `jest.config.ts` | Re-export of `packages/test/jest.config.ts`; adds the turbo `test:unit` task. |
| `tsconfig.jest.json` | Extends `packages/tsconfig/unit-test.json` — the ts-jest `tsconfig`. |
| `__mocks__/` (9 shims) | The shared config resolves them against THIS package's `<rootDir>`. |
| `test:unit` script | Hooks the package into `turbo run test:unit`. |
| devDeps at `catalog:test` | `@baseapp-frontend/test`, jest, jsdom, ts-jest, babel-jest, RTL. |

The nine shims are `console`, `fetch`, `file`, `style`, `next-font`, `react-native`,
`expo-constants`, `expo-modules-core`, `expo-secure-store` — each a three-line re-export of the
matching file in `packages/test/__mocks__/`. Copy them verbatim; the shared jest config never looks
in `packages/test/` for them.

### Relay — +4

| Add | Why |
|---|---|
| `relay.config.js` | Re-export of `packages/config/relay.config.ts`. |
| `schema.graphql` | Committed; regenerated by the `relay:download-schema` script. |
| `__generated__/.keep` + `.gitignore` | Ignore `/__generated__`, un-ignore the `.keep`. |
| `babel.config.js`, `.env`, `.env.example`, 3 scripts | The codegen loop, plus its devDeps. |

`babel.config.js` carries `plugins: ['relay']`. The three scripts are `relay`,
`relay:download-schema`, and `relay:update-schema`, and `build` gains a `pnpm relay &&` prefix so
codegen runs before `tsc`.
`packages/components/package.json` is the only package wired end to end.

### Web components and styling — +3

| Add | Why |
|---|---|
| `tailwind.config.js` | Copy `packages/wagtail/tailwind.config.js` — the deep-import form. |
| `postcss.config.js` | Tailwind + autoprefixer pipeline. |
| A `globals.css` under `styles/` | Only if the package ships CSS; give it an `exports` subpath. |

`packages/design-system/styles/web/tailwind/globals.css` is the shipped example, exported through an
explicit `{ "default": ... }` condition object.

### Cypress component tests — +4

| Add | Why |
|---|---|
| `cypress.config.ts` | Component-test runner config. |
| `webpack.config.ts` | The bundler Cypress component testing runs against. |
| `cypress/support/` (4 files) | `commands.ts`, `component.ts`, `component-index.html`, `types.ts` |
| `test:component` script | Nothing runs the specs without it. |

**This is the one addition that reaches outside the package directory.**
`.github/workflows/main.yml:119-124` hardcodes `--filter @baseapp-frontend/components` across its
four Cypress install steps, so a new package's component tests never run in CI until it is added
there. Failure mode: green CI, zero component tests executed.

### Storybook — +4

| Add | Why |
|---|---|
| `.storybook/main.ts` + `preview.ts` | Story globs and decorators. |
| `public/mockServiceWorker.js` | Pair it with an `msw.workerDirectory` field in `package.json`. |
| `storybook` + `storybook:build` scripts | On a free port — 6006 and 6007 are taken. |
| devDeps at `catalog:storybook` | Keeps the version pinned with every other Storybook consumer. |

Before adding a fifth Storybook instance, consider composing the package's stories into
`packages/components/.storybook/main.ts`, which already globs the design-system stories.

### Nothing else to register

No `pnpm-workspace.yaml` edit — the `packages/*` glob picks the directory up. No `turbo.json` edit —
turbo matches tasks by script name. No `.npmrc`, no `.npmignore`. No CI edit **except Cypress**,
above, which is the single CI-touching step in the whole scaffold.

## Build command

The build is `tsc --build tsconfig.build.json`. There is no bundler step. The canonical script is

```text
"build": "rm -rf dist && tsc --build tsconfig.build.json"
```

as in `packages/authentication/package.json`. A Relay package prefixes codegen —
`rm -rf dist && pnpm relay && tsc --build tsconfig.build.json`, per
`packages/components/package.json` — so generated artifacts exist before the typecheck.

On a Shape B package the build is a typecheck-and-emit gate for CI, not the publish artifact:
`files` omits `dist`, every `exports` target resolves to a `.ts`, and the consumer compiles source.

## Copy from

Copy the scaffold from `packages/components` or `packages/design-system`. They are the two most
recently maintained packages, both on Shape B, and `components` is the only one wired end to end for
Relay, jest, Cypress, and Storybook at once — so its config files are the ones that have been run.

Never copy `packages/wagtail`. Three reasons, each of which produces a package that looks configured
and is not:

- Its Cypress setup is half-built — `cypress.config.ts` and the cypress devDeps are there, but there
  is no `test:component` script and no `cypress/support/` directory, so no spec can run.
- Its Relay wiring is vestigial — `relay.config.js` is present, but `build` never invokes the
  compiler, so `__generated__` goes stale without a signal.
- Its `.gitignore` omits `/__generated__` and `!/__generated__/.keep`, so a copy commits generated
  Relay artifacts on the first run.
